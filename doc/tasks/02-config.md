# 02. Загрузка конфигов и профилей

## Цель

Из YAML-файла получить набор профилей. Каждый профиль описывает один архив:
`src`, необязательные `compress`, `crypt`, `shape`, затем `dst` и `post`.
Любая ошибка конфига обнаруживается при загрузке, до запуска первого процесса.

## Источник

`../raku-bkp/bin/bkp`: `load-profiles`, `render-src`, `load-class`,
`add-middleware`. `../raku-bkp/lib/Bkp.pm6`: подмножества `DirPath`,
`FilePath`, `GzipLevel`, `Cipher`. Описание формата —
`../raku-bkp/README.md`. Отличия — разделы `src.script` и «Config checking»
в `doc/compat.md`.

## Что сделать

Пакет `internal/config`, зависимость `go.yaml.in/yaml/v3`.

- **Один источник.** Если у `src` есть `class`, профиль один. Его имя и
  префикс — имя файла без `.yml`/`.yaml` (регистр расширения не важен).
  Если расширения нет — имя файла в нижнем регистре. Явно заданный
  `dst.prefix` имеет приоритет.
- **Несколько источников.** `src` — словарь `имя → описание`. На каждое имя
  создаётся профиль: свой `src`, независимые копии остальных секций,
  `dst.prefix` = имя. Профили упорядочены по имени.
- **`src.script` + `src.template`:**
  - скрипт запускается через `bash -o pipefail -c`;
  - ненулевой код возврата — ошибка загрузки с кодом и stderr скрипта;
  - пустой вывод — тоже ошибка загрузки;
  - каждая строка вывода подставляется в шаблон вместо `{{ item }}` (пробелы
    внутри скобок допустимы);
  - строка с символами вне `A-Z a-z 0-9 . _ -` — ошибка загрузки, в тексте
    указана сама строка;
  - подставленные куски склеиваются и разбираются как YAML-словарь
    источников.
- **Классы.** Имя класса сравнивается без учёта регистра. Секция класса
  декодируется в структуру этого класса с проверкой известных ключей.
  Классы ещё не реализованы (задачи 04, 05, 07), поэтому здесь нужен механизм:
  таблица `имя класса → конструктор` в пакете пространства имён (`src`,
  `compress`, `crypt`, `shape`, `dst`) и общая функция сборки профиля. Сборка
  вызывается при загрузке, так что неизвестный класс и плохие атрибуты
  обнаруживаются сразу. Конструкторы не запускают процессов и не ходят в сеть.
- **Общие типы для конфигов:**
  - «строка или список строк» для `files`, `exclude`, `dbs`; скаляр-число
    тоже допустим и даёт строку;
  - «команда» для `cmd` и `mount.cmd`: только YAML-список, строка — ошибка с
    подсказкой записать список;
  - проверки «существующий каталог» и «существующий файл»;
  - план `y/m/w/d`: неотрицательные целые, хотя бы одно положительное.
- **Ключи верхнего уровня:** `src`, `compress`, `crypt`, `shape`, `dst`,
  `post`. Любой другой — ошибка.

## Тесты

- все примеры конфигов из `../raku-bkp/README.md` в `testdata/`;
- один и несколько источников, явный `dst.prefix`, имя файла без расширения;
- секции у разных профилей не разделяют общее состояние: изменение одной не
  влияет на другую;
- `script`: успех; ненулевой код; `false | cat` (проверка `pipefail`); пустой
  вывод; недопустимые символы в строке;
- неизвестный ключ, неизвестный класс, класс в другом регистре, `cmd`
  строкой, пустой план.

## Готово, когда

`go test -race ./...` проходит, ревьюеры не нашли blocking, файл задачи
удалён.
