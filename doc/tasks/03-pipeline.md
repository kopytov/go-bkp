# 03. Конвейер процессов

## Цель

Ядро программы: запустить цепочку стадий (источник → сжатие → шифрование →
ограничение скорости), соединив их пайпами так, чтобы данные шли от процесса
к процессу мимо bkp. Дождаться всех процессов, проверить код возврата каждого
и надёжно всё убить при ошибке или сигнале.

## Источник

`../raku-bkp/lib/Bkp/Src.pm6`, `Middleware.pm6`, метод `out` в `Dst.pm6`.
Правила — раздел «Processes and pipes» в `AGENTS.md`. Отличия — разделы
«Every stage's exit status is checked» и «Stage stderr» в `doc/compat.md`.

## Что сделать

Пакет `internal/pipeline`.

- **Стадия** описывается argv, допустимыми кодами возврата (по умолчанию
  только 0) и, при необходимости, дополнительными дескрипторами (понадобятся
  для ключа `openssl`). Первым звеном может быть не процесс, а открытый файл
  (`redis`).
- **Выход цепочки** — `*os.File`, который получатель передаёт дальше:
  - локальный получатель (задача 05) делает его stdin процесса или копирует в
    файл;
  - FTP (задача 07) читает его в Go.
  
  Если читатель-процесс не нужен, выход может сразу быть открытым файлом
  назначения.
- **Пайпы.** Родитель закрывает свои копии концов после `Start`.
- **Группа процессов.** Все процессы профиля — в одной своей группе.
  При ошибке любой стадии, отмене контекста или `SIGTERM`/`SIGINT` группа
  получает `SIGTERM`, а через небольшую паузу — `SIGKILL`. Дальше все
  процессы дожидаются.
- **Итог.** Ошибка, если хоть одна стадия завершилась с недопустимым кодом
  или по сигналу. В тексте: какая стадия, код или сигнал, последние строки её
  stderr (ограниченный буфер, например 20 строк или 4 КиБ). Допустимый
  ненулевой код пишется в лог.
- **stderr стадий** при `BKP_LOG` дополнительно копируется в stderr bkp.

## Тесты

Только поддельные утилиты или тестовый бинарник в роли helper-процесса:

- данные проходят через цепочку из трёх стадий без искажений, объём больше
  буфера пайпа;
- падение первой, средней и последней стадии;
- допустимый ненулевой код (как у `tar` с кодом 1);
- стадия, убитая сигналом;
- зависшая стадия и отмена контекста: всё завершается, зомби и потомков не
  остаётся, функция возвращается;
- стадия, которая порождает собственный дочерний процесс: он тоже убит;
- хвост stderr в тексте ошибки;
- первое звено — файл.

## Готово, когда

`go test -race ./internal/pipeline` проходит стабильно (прогнать с
`-count=20`), ревьюеры не нашли blocking, файл задачи удалён.
