# 09. CI и выпуски на GitHub

## Цель

Проверки идут на каждый push и pull request. Выпуск собирается и
публикуется на GitHub по тегу, который ставит оператор. В README есть
инструкция по установке из опубликованного выпуска.

## Источник

`scripts/test.sh`, `scripts/lint.sh`, `scripts/build.sh`, `mise.toml`,
`README.md`. Репозиторий: `github.com/kopytov/go-bkp`.

## Что сделать

- **Проверки.** Workflow в `.github/workflows/` на push и pull request:
  - инструменты ставятся через `mise` по версиям из `mise.toml`, а не
    своими версиями в workflow;
  - `scripts/test.sh`;
  - `scripts/lint.sh .` — по всему дереву. Без аргументов он смотрит на
    diff от `HEAD`, в CI это пусто: он напишет `nothing to lint` и выйдет
    с 0, ничего не проверив.
- **Выпуск.** По тегу `v*`:
  - `scripts/build.sh`; checkout с тегами (`fetch-depth: 0`), иначе
    версией станет хеш коммита;
  - GitHub Release с `bkp-linux-amd64`, `bkp-linux-arm64`, `SHA256SUMS`;
  - перед публикацией `sha256sum -c SHA256SUMS` и `--version` бинарника
    amd64 в точности равна тегу (без `-dirty`);
  - тег с суффиксом (`v1.0.0-rc1`) публикуется как pre-release.
- **Пакеты.** По умолчанию только бинарники в Release. Если при
  планировании оператор решит, что нужны `.deb`/`.rpm`, инструмент для них
  (например, `nfpm`) идёт в план с тем, что он даёт, и ждёт одобрения, а
  описание поставки в `AGENTS.md` правится под пакеты.
- **Безопасность workflow.**
  - Сторонние actions закреплены по SHA коммита.
  - `permissions` минимальные: `contents: write` только у задания выпуска.
  - Секретов, кроме `GITHUB_TOKEN`, не нужно.
- **README.** Раздел об установке, на английском, как весь README:
  - скачать бинарник своей архитектуры и `SHA256SUMS` из Release;
  - проверить хеш;
  - положить в `/usr/local/bin/bkp`;
  - внешние утилиты ставятся под используемые классы.
- **Вне задачи.** Переход роли `bkp` в `../infrastructure` на бинарник —
  задача того репозитория.

## Готово, когда

Workflow проверок зелёный на `main`. Тестовый тег (pre-release) даёт
Release с бинарниками и хешами, которые проходят проверку. Тестовый
выпуск удалён. README проходит `markdownlint` и вычитан оператором. Файл
задачи удалён.
