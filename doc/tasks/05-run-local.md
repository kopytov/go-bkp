# 05. Локальное хранилище и запуск бекапа

## Цель

Первая полезная версия: `bkp <config>...` делает бекап в локальный каталог,
ротирует его и честно сообщает о неудаче кодом возврата. После этой задачи
бинарник можно ставить на сервер с `dst local`.

## Источник

`../raku-bkp/lib/Bkp/Dst/Local.pm6`, `../raku-bkp/lib/Bkp/Dst.pm6` (`SEND`),
`../raku-bkp/bin/bkp` (`MAIN (*@configs)`, `get-dst`, `log`).
`doc/nonzero-exit-on-failed-backup.md` — разбор инцидента: эта ошибка
не должна переехать. Отличия — разделы «Send first, rotate after»,
«Exit status of `bkp <config>...`», «Error messages go to stderr»,
«Destination setup failures», «Retry pauses», «Signals», «Cleanup after
every attempt», «`post` hook failures», «Permissions» в `doc/compat.md`.

## Что сделать

**`dst local`** (`internal/dst/local.go`):

- атрибуты: `dir` (обязателен), `plan`, `no-rotate`, `prefix`, `mount`
  (`point`, `cmd` — список, `umount` — bool);
- **mount:**
  - если `mountpoint -q <point>` вернул 0, ничего не делать;
  - иначе выполнить `cmd`, а без него `mount <point>`;
  - затем повторно проверить `mountpoint`, точка должна быть смонтирована;
- **umount:** только при `umount: true` и если точка смонтирована;
- **запись архива:**
  - выход конвейера пишется прямо в файл `.<archive>.partial`, создаваемый с
    правами `0600`, без промежуточного копирования, если это возможно;
  - после успеха всех стадий: `Sync`, `Close` с проверкой ошибки, `rename` в
    итоговое имя;
  - при неудаче временный файл удаляется;
- листинг: имена и размеры файлов каталога;
- удаление архива по имени. Имя не может выйти за пределы `dir`.

**Запуск** (`internal/run`, плюс `cmd/bkp`). В сообщениях `<config>` — имя
файла конфига без каталога, как в Raku:

- **Порядок.** Конфиги обрабатываются по порядку аргументов, профили — по
  имени.
- **Конфиг не загрузился.** Сообщение
  `<config> loading failed - skipping` и текст ошибки в stderr, отметка о
  неудаче, переход к следующему конфигу.
- **Попытки профиля.** До 10 попыток. После неудачной попытки N (с нуля)
  пауза `N*180` секунд, после последней паузы нет. Паузу прерывает сигнал.
  В тестах длительность паузы подменяется.
- **Шаг попытки:**
  1. подготовить получатель (mount);
  2. выбрать имя архива;
  3. запустить конвейер;
  4. записать архив;
  5. ротировать, если нет `no-rotate`.

  Ошибка на любом шаге, включая mount, — неудачная попытка:
  `<config>:<name> failed [N]` и `<config>:<name> exception: <ошибка>` в
  stderr.
- **После каждой попытки** — удачной или нет — очистка источника и umount.
- **Профиль исчерпал попытки.** `BACKUP <config>:<name> FAILED!` в stderr,
  отметка о неудаче.
- **`post` после успеха** запускается через `bash -o pipefail -c`. Если хук
  упал, в stderr сообщение с кодом и отметка о неудаче. Повтора нет.
- **Сигналы.** `SIGTERM`/`SIGINT` отменяют текущую попытку: процессы
  убиваются, очистка выполняется, временный файл удаляется. Оставшиеся
  профили и конфиги не запускаются, код возврата ненулевой.
- **Код возврата:** 0 только если все конфиги загрузились, все профили
  удались и все хуки отработали.
- **Лог прогресса** при `BKP_LOG` пишется в stdout в формате Raku
  `<время ISO 8601 до секунд с зоной> bkp: [<pid>] <сообщение>`, с теми же
  сообщениями (`started`, `finished`, `Got configs`, `Got profiles`, …).

## Тесты

Сквозные, на `t.TempDir()` с поддельными утилитами. Сценарии из
`nonzero-exit-on-failed-backup.md` обязательны:

- конфиг со `src.script: "false"` рядом с рабочим: рабочий забекаплен, код
  возврата ненулевой, в stderr код возврата скрипта;
- то же с `src.script: "false | cat"`;
- профиль, у которого dst не монтируется: остальные конфиги отработали, код
  ненулевой;
- все конфиги рабочие: код 0, архивы на месте, вывод как ожидается.

Плюс:

- падение стадии: архива нет, `.partial` нет, старые архивы не удалены;
- удача со второй попытки;
- повторный запуск в тот же день заменяет архив;
- ротация после удачи;
- права `0600`;
- очистка и umount после неудачной попытки;
- падение `post`;
- сигнал посреди отправки.

## Готово, когда

`go test -race ./...` проходит. Ручная проверка: `tar` + `gzip` → `local` на
настоящих утилитах; архив разворачивается; `echo $?` после сломанного
конфига ненулевой. Ревьюеры не нашли blocking, файл задачи удалён.
